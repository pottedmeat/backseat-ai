# A run is a private, per-user directory named for its root actor

Nothing runs between invocations to hold a run id ([ADR-0003](0003-cli-rehydrates-per-invocation.md)), so an invocation has to find its run from what it is given: an actor id. Everything about a run — the root's record with its children inside it, the trace, and while it is live the pin of the code it started with — has to sit somewhere that id leads to.

**A run is one root actor's directory, named after the root and found from any actor's id prefix. Live runs sit under `$XDG_STATE_HOME/backseat/runs`; the invocation whose response shows the root `done` or `error` sheds the pin and moves the directory to `<tmpdir>/backseat-<uid>/runs`. Both default locations are private to the user (mode `0o700`), and a directory there that another user owns is refused.** Calls that touch no actor (usage, a call naming an unknown actor) are traced into a run-less file beside the live runs.

Live runs go under the state home because nothing purges it mid-run. A completed run keeps its record and its trace, which is the whole of what is left once the pin is shed: the pin's digest stays on the root's record, so a finished run still says which code it ran. `backseat-ai doctor` proposes removing live runs nobody has called in a while, and `backseat-ai report` lists live and completed runs alike.

The directories are private because a run's files hold full payloads and the source of the code it ran. The completed location carries the user's id in its name because a shared `/tmp/backseat` belongs to whoever made it first, and anyone else's runs would then be written where that user can read them. Refusing a directory another user owns is the only safe answer on a shared temp directory; the error says to point `TMPDIR` and `XDG_STATE_HOME` somewhere of the user's own.

Both locations can be moved by the `runs.live` and `runs.completed` keys of `$XDG_CONFIG_HOME/backseat/config.json` (`~` allowed, a relative path read from the config file's directory), never by a project file: where a person keeps their runs is theirs, not the project's. `BACKSEAT_STATE_DIR` pins one directory as the run for a harness; a pinned directory may hold several roots and never moves.

A run also gets a **scratch directory**, `<tmpdir>/backseat-<uid>/scratch/<rootId>`, made at `create` and named on the root's record. It is a sibling of the run, not part of it: what a machine writes there is a courier for another actor's driver to read, never the record, since the values it carries already persist in the context and the trace. It is removed when the run completes, at the same moment as the pin, so a path into scratch is valid exactly as long as the run is live. `currentRun()` and `scratchDir()` tell a machine's own implementations which run they are in and where its scratch is; `currentRun()` is ambient because an implementation is a plain function with no other way to learn it, and a test sets it through `setCurrentRun()`.

We chose this over a per-project directory, which every run from the project appended into forever, so the report could not tell runs apart. The costs: a second root started to finish what a stuck one could not is a second run in the report, unless the harness pinned a directory; a run abandoned before it finished stays live until `doctor` proposes removing it; and a completed run in the temp directory can be reclaimed by the OS, which loses the only copy of its log.
