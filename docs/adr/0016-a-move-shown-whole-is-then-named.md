# A move shown whole is then named, and a schema already shown says to call `describe`

Every response lists the moves offered now. Printed whole each time, with each destination heading and description, each move's description, its `Requires:` line and its schema, the list costs about 4K tokens a response to say again what the first response in that state said. A targetless read declared on the root, offered in every state, made it worse: one arrival re-sent 46 unchanged schemas, 8.8 KB.

**A move printed whole is recorded against the state the actor is in, and while its text is unchanged it is then printed by name.** The tracking slice's `listed` keys each move by the actor's active atomic state ids, the event and the destination, and holds a digest of the move's rendered text (destination description, move description, `Requires:` line, schema). A digest, because the text of every move in every state would swell the persisted snapshot. A move whose key holds the same digest is printed after the whole ones as `- event → target`, under one line saying each was shown in full on an earlier response in this state and to call `describe <event>` to see one whole. A destination whose every move is named loses its heading. A move never printed whole in this state, or whose text changed, is printed whole and recorded. "In a state" is over the actor's life, matching `visited`: a state re-entered later gets its revisit instructions and its moves by name. If drivers lose track of moves after a long absence, keying `listed` by the stay is the alternative.

**A schema is printed only when its text differs from what this actor was last shown for that move** (`context.agent.shown`). The entry is keyed by the move's destination, or for a move with none, by the node that declares it, so a read declared on the root is shown once per actor in every state rather than once per state. A move printed whole whose schema was withheld says so in one line under its heading: `call describe <event.type> to see its schema`. Without that line the move read the same as one that takes no payload.

`describe <actorId>` prints every move whole and records them; `describe <actorId> <event>` always prints its schema and never the line ([ADR-0015](0015-describe-takes-just-the-event.md)). The drive protocol says that a move shown whole is named alone on later responses in that state, until it changes, and that `describe <actorId> <event.type>` prints it whole again.

The cost is a driver that must remember what it was shown, or call `describe` to see it again.
