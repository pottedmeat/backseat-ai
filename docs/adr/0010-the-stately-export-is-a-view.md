# The Stately export is a view, and it goes one way

A person looking at a Backseat machine wants to see it, and Stately Studio draws XState machines. Studio's importer reads code without running it and keeps only the keys XState knows.

**`node cli.ts stately [<machine>...] [--out <dir>]` writes each catalog machine, and each machine it spawns, as an XState `setup().createMachine()` file to paste into Studio, one machine per file. It is a view: nothing reads the file back, and the machine value stays the only thing ever edited.**

It is a person's command, beside `lint`, so the agent's surface stays the agent's ([ADR-0001](0001-cli-targets-agents-not-humans.md)), and the machine stays one TypeScript value ([ADR-0005](0005-a-machine-is-one-typescript-value.md)) with no second format to keep in step. It reads the **built** machine, as the lint does, so what it draws is what registration accepted.

The export moves Backseat's keys to where Studio shows them. `instructions` — both visits where they differ — goes into the state's or transition's `description`; a payload's fields with their `.describe()` text go into the transition's `description` and its JSON Schema into `meta`; what `data` hands the agent goes into the description as its type. Guards and actions become named implementations, a hoisted guard under its `const`'s name. The machinery the compiler adds — the tracking slice of context, the runtime's own `on` keys, the note behind a spawn, the stop that ends a collection — is left out, because no author wrote it and no agent sends it.

A spawn is drawn as a purple transition, `spawn:<src>`, from the state that spawns to where the collecting transition goes, since Studio draws no spawned actor. The spawned machine is in its own file, `<name>.<src>.stately.ts`, and the parent's `setup({ actors })` names that file by its path: Studio's importer drops an actor whose value is a name imported from another file and keeps any other expression, so the path reaches Studio and tells the person which file to paste. Tags carry what the canvas cannot draw: `spawns:<src>`, `effect:<event>` for a transition's effect, `refines:<event>` for a payload check beyond its types, and `may-refuse:<event>` for an action or effect that throws `RejectedEvent`.

The costs: the view is lossy and cannot be otherwise — implementations reach Studio as source text it cannot run, `spawn:<src>` is listed among the machine's events though no agent can send it, and an actor named by a path is not logic XState would take, so a type checker flags the file. `may-refuse` is read off the source, so a throw inside a helper is missed. And `data`'s type needs the TypeScript checker, which TypeScript 7 has no JavaScript API for, so the command looks for TypeScript 5 when it runs — `typescript5`, an alias beside TypeScript 7, or a `typescript` that has the API, from the catalog's directory — and fails naming what to install when it finds none. Nothing else needs it, so it is not a dependency of the package.
