# An action may refuse the event it runs for

A guard hides a transition, and the agent is told nothing ([ADR-0001](0001-cli-targets-agents-not-humans.md)). Some objections are only knowable at the moment of acting and are worth explaining: the file the agent names already exists, so send a different name or `overwrite: true`.

**An action may throw `RejectedEvent` to refuse the event it runs for. The runtime unwinds to the persisted record and answers a rejection with reason `refused` carrying the message; the actor does not move and the call is traced like any other rejection. A transition refuses in its `effect`, which runs before any action; an action that must refuse touches nothing outside the machine. The schema stays the whole of what the agent may send.**

A guard answers "what can I do?"; a refusal answers "why can't I do that?". A guard reads context, so it can only hide a move the context already proves invalid. A refusal runs with the event in hand, so it is for what cannot be known until then: an externality, values that conflict with each other, a check a schema cannot express. Turning such a case into a guard leaves the agent at a dead end it cannot reason past.

An action's refusal happens mid-transition, and nothing can make it go first: the source state's exit actions run before the transition's own, and building the machine cannot tell a refusing action from any other. The unwind restores everything inside the machine, and nothing outside it. So a transition's [`effect`](0011-a-transition-may-run-the-tool-it-guards.md), which runs before any action, is where to refuse, and an action that must refuse instead writes nothing outside the machine, so the unwind leaves nothing behind. A key a refusal asks for, like `overwrite`, is declared in the schema of every transition that uses the action, so the contract the agent is shown is complete. `RejectedEvent` is recognised by name rather than `instanceof`, since a machine's code may hold its own copy of the module. Any other throw from an action is an error: the actor errors, except on a collecting transition, which is unwound and answered `action-failed` ([ADR-0008](0008-an-actor-never-changes-under-its-driver.md)).

We rejected a separate pre-send refusal position as a second implementation kind no use needed. The invariant is that a rejected event never moves the actor.
