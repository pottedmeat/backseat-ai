unsolicited guidance, every mile

A workflow in the back seat, nagging your agent through every step.

Graph-based workflows for coding agents.

A workflow is a graph: states, the transitions between them, and the instructions for each. The agent reaches a state and is told what to do there and which transitions are open; anything else is refused with a reason. Most frameworks call the model and decide its next step; Backseat tells the model which steps are open and lets it choose.

don't worry, I wrote it down

Everything the agent is told is read off the notes, never the notes themselves.

Everything the workflow knows lives in one context: the question, the round it is on, the sub-tasks still queued, the findings so far. A transition writes to it; a state reads from it. Instructions, schema and data are written as functions of context and computed each time the agent reaches a state, and the agent is handed exactly what that state declares. Nothing else in context reaches it.

Instructions arrive with the state, not before it.

Every state and every transition carries a one-line description: a clarification of what it is, read while the agent is choosing. There are no instructions in it. Instructions are what a state hands the agent by being reached, computed from context and from whether this is a first visit or a return. So the agent commits to a transition before it reads a word of what it will be asked to do there.

Every transition is a checkpoint: the agent proves it has what the next state needs.

The schema is what the agent has to produce to get through, printed under the move while the agent is still choosing, so the proof is never a guess. It can be computed from context, so what a checkpoint asks for can depend on where the run is. A state can carry a schema of its own, the price of entering it by whichever transition arrives; the runtime extends it with the transition's, and the agent reads one contract.

hold on, I've got a gadget for that

The workflow brings its own tools, and uses them on the way.

Some of the work in a workflow is not the agent's to do: a lookup, a call to a service, a judgment the workflow would rather make itself. Backseat puts that work on the transition, as an effect: it runs when the agent takes the move, after the checks have passed. Whatever the tool brings back rides the event, and the author decides what of it goes into context and what goes straight to the agent. The agent sends the event and reads what came back; it never holds the tool.

The workflow keeps the record; the agent is read the part it needs, where it needs it.

Context is the run's one record: what the agent sent, what an effect brought back, what an action worked out, each kept as it was written for as long as the run lasts. A state can declare data: the part of that record the agent is handed while it is there, on every visit. A line written on the first call reads the same on the sixty-ninth, after six workers have come and gone, so the agent is shown the record, not its recollection of it. Any agent holding the actor's id reads the same record with snapshot. What a state does not declare stays hidden.

here's who to call and what to tell them

The workflow writes the list; the agent makes the calls.

A subagent that needs a workflow of its own gets one, with a context of its own. The agent makes the call. It starts the subagent in its own harness and tells it to run the listed command, and that is the whole handoff, because once in the seat the subagent has a backseat driver of its own, with its own instructions, its own refusals and its own record, told only its input. When it is done, Backseat collects its output and merges it into the parent's context at the workflow's discretion. Only what the calling agent needs is surfaced to it.

I'll tell you everything, once we're on the road

The agent reads nothing before it starts and, even then, only what it needs.

Most agents start under a wall of instructions: every rule, every step, every case, read before anything has happened and carried through everything after. Here there is nothing to read first. The agent starts the workflow, and from then on it is told what it needs when it needs it: what to do in the state it is in, which transitions are open from there, and nothing about the rest of the workflow until it gets there.

Some reasons to refuse only turn up mid-move.

While a guard can keep a transition from being shown, some reasons to refuse are only found partway through the move: an effect or an action finds one, and says so in the author's words. The workflow rejects the event with that message, says the actor has not moved, and prints the arrival again, so the next call is the corrected one.

The workflow continues until the subagents' work is needed.

While the subagents work, the workflow keeps going. The first move that needs what they produce is held until all of them have finished. Sent early, it is refused, naming the subagents still incomplete. Sent once they are back, it brings their work into context.

Every call is in the record, and the report walks you through it.

Every call an agent makes lands in the record: the state the actor was in, the move it took or was refused and the reason, and what an effect brought back. The trace report draws each actor's journey from it, the states it stopped in and the calls answered from each. A run is assessed from the workflow's record, never from the agent's account. That is how a workflow improves: a wrong turn sits under one state, so the instructions to fix are that state's. Fix them, run again, and the next report says whether it worked.

I've seen how you drive without me

A workflow that is enforced, not described.

Backseat came from wanting more from workflows that ran on instructions alone. Each was a long prompt describing the steps, and even a frontier model treated it as a description: mostly followed, never enforced. The want was a workflow that holds its shape whichever model is in it.

So the shape is written down and enforced. You decide what can happen: the states, the transitions out of each, the guard on each one, the schema it must be sent with. The model decides what does. The workflow is semi-deterministic: every step is fixed, and the rest is the model's judgment, what it does inside the step it is in and, where more than one transition is open, which one it takes.

A model handed one step at a time, with its instructions and its schema, and refused with a reason when it strays, runs a workflow it could not have run from the prompt. It does not have to be a frontier model. A cheaper one, in the same workflow, handles multi-step work it could not on its own.

three roads. all of them signposted

Every command says where it runs.

One command comes with the package and reads no project: npx backseat-ai. Everything that reads your machines runs through your project's own cli.ts, which init writes: your commands plainly, the agent's under --drive.

npx backseat-ai …from anywhere · reads no project
initSets the working directory up as a project: package.json, tsconfig.json, cli.ts and a catalog. Finishes whatever is missing; replaces nothing you wrote without a yes.
reportLists the runs it can find and renders one as a trace report. report <prefix> picks a run by its root id; report <dir> renders any directory holding a trace.
output <actorId>Prints a finished actor's output.
doctorProposes removing live runs nobody has touched in 14 days.
node cli.ts …in your project · your project's front
lintReports what the style rules can establish about each machine of the project.
statelyWrites each machine, and the machines it spawns, as a file to import into Stately Studio.
node cli.ts --drive …the agent's tool · the same front, under --drive
create <machine>Starts a fresh actor. The response is its id, its state and the transitions enabled from there.
send <actorId> <event> [payload | -]The only way to move an actor. Payload keys follow the schema shown for that event; - reads the JSON from stdin.
snapshot <actorId>The current state and enabled transitions, unchanged. How to orient when handed an id.
describe <actorId> [<event>]With an event, that one move and its schema; without, the current state with its full first-arrival instructions.
